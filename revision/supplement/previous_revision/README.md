# Auxiliary loss weight and delayed recall

This supplement tests one endpoint chosen before outcomes on the new seeds were computed. Read analysis_plan.md for the design. The plan was recorded locally, without public preregistration. Fresh seeds are 1000–1023; original seeds were 0–11. The output is 96 fresh seed–weight rows. At 60 updates and a 16-step delay the mean paired next-texture minus choice-only difference is −12.02 percentage points for the primary auxiliary weight of 0.5 (percentile bootstrap interval −19.96 to −4.96). The other weights are exploratory.

1. Obtain the original repository at https://github.com/VEDANT1602/delayed-cue-recall/tree/686f4f7e50229f061b4efdc5cb5d3f4812a2fc48 .
2. From this supplement directory, run `python -m pip install -r requirements.txt`, then `python run.py /path/to/delayed-cue-recall/run.py`. The reference file SHA-256 is checked by this script. The two CSVs are regenerated locally. The revision used CPU PyTorch 2.9.1, NumPy 2.3.5, Python 3.12.14.
3. To check the original study, run its own `python verify.py`, `python run.py` and `python verify.py` from a writable checkout. Retraining while revising this paper matched all 720 decision counts and all 720 erased-cue counts. Of the 720 next-texture accuracies, one changed from 0.22747802734375 to 0.2274169921875 (choice-only, seed 0, update 20, delay 16, an auxiliary head without supervision). This is one transition in 16,384. All other fields matched.

The extension was also run at weights 0 and 0.5 for the original seeds 0–11. All 24 sets of choice, cue-erasure and texture-prediction outcomes at the supplement endpoint matched the original archive.

No custom data download or hardware device is required. Inputs are regenerated by the reference code. The original repo has no identified license at this commit. Software reuse permissions should be set by its rights holder. This supplement makes no license grant for the original software.

## Environment lock

Create separate Linux x86_64 virtual environments with CPython 3.12.14 for the revision and 3.11.9 for the baseline. In the activated revision environment run `python -m pip install --require-hashes -r revision-cp312-linux-x86_64.lock`. For the original checkout, install `baseline-cp311-linux-x86_64.lock` the same way in the baseline environment, then run the commands above. Both locks explicitly select the CPU build of PyTorch 2.9.1. The baseline lock includes the published plotting stack. For fresh-seed training, use the 3.12 environment and pass the pinned source run.py path to the supplement. The lock headers identify the platform; the baseline transitive pins reconstruct a compatible environment for the published direct requirements.
